# Glossaire

*Tableau 46 : Glossaire technique normalisé*

- **AC (Alternating Current / Composante alternative)** : Fraction variable et dynamique du signal photopléthysmographique, directement liée aux pulsations sanguines systoliques et diastoliques de l'onde de pouls.
- **ADC (Analog-to-Digital Converter / Convertisseur analogique-numérique)** : Circuit électronique transformant une tension électrique continue en une valeur binaire échantillonnée (ex. convertisseur 18 bits du MAX30102).
- **AMCL (Adaptive Monte Carlo Localization)** : Algorithme probabiliste de localisation de robot mobile basé sur un filtre à particules.
- **API (Application Programming Interface)** : Interface normalisée permettant à des applications logicielles distinctes d'échanger des données et des commandes.
- **BLE (Bluetooth Low Energy)** : Technologie de communication radiofréquence sans fil à faible consommation énergétique intégrée au SoC de l'ESP32.
- **BPM (Beats Per Minute / Battements par minute)** : Unité normalisée de mesure de la fréquence cardiaque corporelle.
- **CAN / Controller Area Network** : Bus de communication série différentiel très utilisé dans l'industrie automobile et la robotique lourde.
- **DC (Direct Current / Composante continue)** : Fraction quasi constante du signal optique transmise à travers la peau, représentative de l'absorption par les tissus cutanés stables, les os et le sang veineux non pulsatile.
- **DS18B20** : Sonde thermométrique numérique intégrée communiquant par le protocole propriétaire 1-Wire sur un fil unique de données.
- **ESP32** : Microcontrôleur basse consommation 32 bits à architecture Xtensa LX6 produit par Espressif, intégrant le Wi-Fi, le Bluetooth et de multiples périphériques matériels (UART, SPI, I²C, PWM).
- **FIFO (First In, First Out)** : Tampon mémoire matériel où la première donnée enregistrée est la première restituée (ex. registre FIFO à 32 échantillons du MAX30102).
- **FSM (Finite State Machine / Machine à états finis)** : Modèle formel de comportement décrivant un système sous forme d'un ensemble discret d'états et de transitions conditionnelles (ex. états `IDLE`, `DECIDE`, `FORWARD`, `TURN`, `BLOCKED`).
- **GPIO (General Purpose Input/Output)** : Broche logicielle polyvalente d'un microcontrôleur pouvant être configurée dynamiquement en entrée logique ou en sortie de puissance.
- **HMI / IHM (Human-Machine Interface / Interface Homme-Machine)** : Ensemble des dispositifs logiciels et matériels (écrans tactiles, synthèse vocale, boutons) permettant l'interaction entre l'usager humain et le système robotique.
- **HMAC (Hash-based Message Authentication Code)** : Algorithme cryptographique garantissant l'intégrité et l'authenticité d'un message par application d'une fonction de hachage à clé secrète.
- **HTTP / HTTPS (Hypertext Transfer Protocol Secure)** : Protocole de transfert hypertexte régissant les échanges sur le Web, sécurisé par le chiffrement TLS.
- **I²C (Inter-Integrated Circuit)** : Bus synchrone série bifilaire (SDA, SCL) inventé par Philips, permettant de raccorder plusieurs périphériques esclaves sur deux broches de microcontrôleur.
- **LiDAR (Light Detection and Ranging)** : Télémètre optique mesurant les distances aux obstacles environnants par émission d'impulsions laser infrarouges et mesure de temps de vol.
- **LLM (Large Language Model / Grand modèle de langage)** : Réseau de neurones profond entraîné sur de gigantesques volumes textuels pour comprendre et générer du langage naturel (ex. Gemini 2.5 Flash, Qwen 2.5).
- **LRU (Least Recently Used)** : Politique de gestion d'un cache mémoire évacuant prioritairement les éléments les moins récemment consultés pour libérer de l'espace.
- **MAX30102** : Capteur biométrique de surface associant deux diodes électroluminescentes (rouge 660 nm et IR 880 nm) à une photodiode sensible pour l'oxymétrie de pouls et la fréquence cardiaque.
- **NLU (Natural Language Understanding)** : Sous-domaine de l'intelligence artificielle traitant de l'extraction sémantique et de l'identification des intentions à partir de textes bruts.
- **OneWire (1-Wire)** : Protocole de bus asynchrone propriétaire développé par Dallas Semiconductor permettant de communiquer à vitesse modérée sur un conducteur unique de données et une masse commune.
- **Ollama** : Environnement d'exécution et serveur d'inférence open-source permettant de faire tourner des modèles de langage quantifiés (LLM) directement sur CPU/GPU local en environnement Linux.
- **PPG (Photopléthysmographie)** : Technique optique non invasive mesurant les variations volumétriques locales de microcirculation sanguine au cours du cycle cardiaque.
- **PWM (Pulse Width Modulation / Modulation de largeur d'impulsion)** : Technique permettant de faire varier la puissance moyenne délivrée à un actionneur par découpage temporel périodique d'une tension continue à rapport cyclique variable.
- **Qwen 2.5 0.5B** : Modèle de langage ultra-compact de 500 millions de paramètres développé par Alibaba Cloud, optimisé pour l'inférence locale en bordure de réseau (*Edge AI*).
- **RAG (Retrieval-Augmented Generation)** : Architecture combinant la recherche documentaire ciblée dans une base de connaissances vectorielle et l'injection dynamique des passages pertinents dans le prompt d'un LLM.
- **ROS 2 (Robot Operating System 2)** : Ensemble d'outils, bibliothèques et conventions logicielles open-source dédiés à la création d'architectures robotiques modulaires et distribuées.
- **SLAM (Simultaneous Localization and Mapping)** : Problématique algorithmique consistant pour un robot mobile à cartographier un environnement inconnu tout en s'y localisant simultanément.
- **SpO2 (Saturation Pulsée en Oxygène)** : Fraction volumique d'hémoglobine oxygénée par rapport à l'hémoglobine totale circulante dans le sang artériel pulsatile, exprimée en pourcentage.
- **SQLite3** : Moteur de base de données relationnelle transactionnelle serveurless, compact, auto-contenu et embarqué dans les applications.
- **STT (Speech-To-Text / Reconnaissance vocale)** : Conversion automatique d'un flux audio de parole humaine en texte informatique manipulable.
- **Ticket** : Identifiant formalisé unique attribué à un usager s'inscrivant dans la file de consultation d'un médecin (ex. `A-MAT-1`).
- **Topic** : Canal de communication unidirectionnel et typé dans le middleware ROS 2, permettant la publication et la souscription asynchrones de messages entre nœuds.
- **TTS (Text-To-Speech / Synthèse vocale)** : Conversion automatique d'une chaîne textuelle en flux sonore articulé audible pour l'humain.
- **UART (Universal Asynchronous Receiver-Transmitter)** : Périphérique matériel gérant la transmission asynchrone de données série sur deux lignes distinctes d'émission (TX) et de réception (RX).
- **UIT-T** : Secteur de la normalisation des télécommunications de l'Union Internationale des Télécommunications, publiant les recommandations fondamentales pour l'Internet des objets (dont UIT-T Y.4000).
- **WPA2 (Wi-Fi Protected Access 2)** : Protocole de sécurisation des réseaux locaux sans fil basé sur l'algorithme de chiffrement par blocs AES-CCMP.
- **X-Doctor-Token** : En-tête de sécurité HTTP spécifique véhiculant un jeton cryptographique à longue durée de vie autorisant l'accès aux interfaces médicales.
- **X-Staff-Token** : En-tête de sécurité HTTP véhiculant le jeton administratif autorisant le personnel de santé à configurer les files d'attente et sessions.

## Annexe 3 : Extraits de code fondamentaux du firmware ESP32 et des composants logiciels

### Extrait 3.1 : Boucle d'arrêt d'urgence matérielle et temporisation de commande (Firmware C++)

```cpp
// --- Extrait du firmware ESP32 : esp32_firmware_integration.ino ---
// Gestion déterministe de la sécurité motrice en cas d'obstacle frontal immédiat

const unsigned long MAX_MOVE_DURATION_MS = 2000; // Timeout de sécurité sans heartbeat ROS
const float CRITICAL_STOP_DISTANCE_CM   = 25.0f; // Seuil matériel de coupure immédiate

void handleSafetyChecks() {
    unsigned long now = millis();
    
    // 1. Coupure par expiration temporelle de la commande de déplacement
    if (currentMotionMode != MODE_IDLE && (now - lastMotionCommandMs > MAX_MOVE_DURATION_MS)) {
        setMotorMode(MODE_IDLE);
        Serial.println("SAFETY,TIMEOUT_EXPIRED,STOP");
        return;
    }
    
    // 2. Détection d'obstacle critique frontal (< 25 cm) pendant l'avance
    if (currentMotionMode == MODE_FORWARD) {
        float frontDist = getFilteredUltrasonicDistance(SENSOR_FRONT);
        if (frontDist > 0.0f && frontDist < CRITICAL_STOP_DISTANCE_CM) {
            setMotorMode(MODE_IDLE); // Forçage immédiat du PWM à 0 sur L298N
            Serial.printf("SAFETY,EMERGENCY_STOP,FRONT_OBSTACLE,%.1f\n", frontDist);
        }
    }
}
```

### Extrait 3.2 : Multiplexage ultrasonique séquentiel à 35 ms et filtre médian 3 points (Firmware C++)

```cpp
// --- Extrait du firmware ESP32 : Acquisition démultiplexée des 3 capteurs HC-SR04 ---

const unsigned long PING_INTERVAL_MS = 35; // 35 ms d'amortissement acoustique inter-ping
unsigned long lastPingMs = 0;
int currentSensorIndex = 0; // 0: FRONT, 1: LEFT, 2: RIGHT

float distanceHistory[3][3] = {{0}}; // Fenêtre glissante de 3 échantillons par capteur
int historyIndex[3] = {0};

float computeMedian3(float a, float b, float c) {
    if ((a <= b && b <= c) || (c <= b && b <= a)) return b;
    if ((b <= a && a <= c) || (c <= a && a <= b)) return a;
    return c;
}

void pollUltrasonicSensors() {
    unsigned long now = millis();
    if (now - lastPingMs < PING_INTERVAL_MS) return;
    lastPingMs = now;

    // Déclenchement impulsionnel du capteur courant
    int trigPin = getTrigPin(currentSensorIndex);
    int echoPin = getEchoPin(currentSensorIndex);

    digitalWrite(trigPin, LOW);
    delayMicroseconds(2);
    digitalWrite(trigPin, HIGH);
    delayMicroseconds(10);
    digitalWrite(trigPin, LOW);

    long duration = pulseIn(echoPin, HIGH, 30000); // Timeout 30 ms (équivalent à ~5 mètres)
    float rawCm = (duration == 0) ? 400.0f : (duration * 0.0343f / 2.0f);

    // Enregistrement et calcul de la médiane sur 3 points
    distanceHistory[currentSensorIndex][historyIndex[currentSensorIndex]] = rawCm;
    historyIndex[currentSensorIndex] = (historyIndex[currentSensorIndex] + 1) % 3;

    float medianCm = computeMedian3(
        distanceHistory[currentSensorIndex][0],
        distanceHistory[currentSensorIndex][1],
        distanceHistory[currentSensorIndex][2]
    );

    // Publication de la trame série : SENSOR,FRONT,42.5
    Serial.printf("SENSOR,%s,%.1f\n", getSensorName(currentSensorIndex), medianCm);

    // Passage séquentiel au transducteur suivant
    currentSensorIndex = (currentSensorIndex + 1) % 3;
}
```

### Extrait 3.3 : Chaîne photopléthysmographique et calcul du ratio $R$ de la $\text{SpO}_2$ (Firmware C++)

```cpp
// --- Extrait du firmware ESP32 : Calcul de SpO2 et BPM via le composant MAX30102 ---

void processPhotoplethysmography() {
    uint32_t irValue  = particleSensor.getIR();
    uint32_t redValue = particleSensor.getRed();

    // Vérification de la présence effective d'un doigt sur le capteur
    if (irValue < 50000) {
        vitalsResetBeats();
        return; // Aucun doigt détecté ou contact insuffisant
    }

    // Détection de pic systolique sur la composante pulsatile IR
    if (checkForBeat(irValue)) {
        unsigned long currentBeatMs = millis();
        if (lastBeatMs > 0) {
            float deltaMs = (float)(currentBeatMs - lastBeatMs);
            float calculatedBpm = 60000.0f / deltaMs;
            if (calculatedBpm >= 40.0f && calculatedBpm <= 200.0f) {
                currentHeartRateBpm = (int)calculatedBpm;
            }
        }
        lastBeatMs = currentBeatMs;
    }

    // Extraction des composantes continues (DC) et alternatives (AC)
    float dcRed = filterDc(redValue, &dcFilterRed);
    float acRed = redValue - dcRed;

    float dcIr  = filterDc(irValue, &dcFilterIr);
    float acIr  = irValue - dcIr;

    // Calcul du ratio de modulation R et déduction de la SpO2
    if (dcRed > 0.0f && dcIr > 0.0f && acIr != 0.0f) {
        float ratioR = (acRed / dcRed) / (acIr / dcIr);
        float estimatedSpo2 = 110.0f - 25.0f * ratioR;

        if (estimatedSpo2 >= 70.0f && estimatedSpo2 <= 100.0f) {
            currentSpo2Percent = estimatedSpo2;
        }
    }
}
```

```python
        if self.invert_steering:
            if command == "TURN_LEFT":
                target_hw_cmd = "TURN_RIGHT"
            elif command == "TURN_RIGHT":
                target_hw_cmd = "TURN_LEFT"

                target_hw_cmd = command

            target_hw_cmd = command

        serial_payload = f"CMD,{target_hw_cmd}\n"
        self.serial_port.write(serial_payload.encode('ascii'))
```

### Extrait 3.5 : Routeur d'IA hybride avec basculement automatique Gemini $\to$ Qwen local (Python)

```python
# --- Extrait de src/hospital_robot/hospital_robot/voice_intent_parser.py ---
# Architecture duale : Priorité Google Gemini 2.5 Flash, Fallback local Qwen 2.5 (Ollama)

import requests
from google import genai

class DualEngineIntentParser:
    def __init__(self, gemini_api_key: str, ollama_url: str = "http://127.0.0.1:11434"):
        self.gemini_client = genai.Client(api_key=gemini_api_key) if gemini_api_key else None
        self.ollama_url = ollama_url
        self.cache = LRUCache(maxsize=128)

    def parse_intent(self, text: str) -> dict:
        # Étape 1 : Moteur réflexe Regex (< 1 ms)
        reflexe = self.match_reflexe(text)
        if reflexe:
            return reflexe

        # Étape 2 : Cache mémoire (< 1 ms)
        if text in self.cache:
            return self.cache[text]

        # Étape 3 : Tentative prioritaire sur le Cloud via Google Gemini 2.5 Flash
        if self.gemini_client:
            try:
                response = self.gemini_client.models.generate_content(
                    model='gemini-2.5-flash',
                    contents=self.build_prompt(text),
                    config={'response_mime_type': 'application/json', 'timeout': 2.0}
                )
                result = json.loads(response.text)
                self.cache[text] = result
                return result
            except Exception as e:
                # Log transparent et déclenchement automatique du mode de secours Edge
                logger.warning(f"[IA Hybride] Défaillance Gemini Cloud ({e}) -> Basculement Qwen local")

        # Étape 4 : Fallback local souverain via Qwen 2.5 0.5B sous Ollama
        try:
            payload = {
                "model": "qwen2.5:0.5b",
                "prompt": self.build_prompt(text),
                "stream": False,
                "format": "json"
            }
            res = requests.post(f"{self.ollama_url}/api/generate", json=payload, timeout=5.0)
            result = json.loads(res.json()["response"])
            self.cache[text] = result
            return result
        except Exception as e:
            logger.error(f"[IA Hybride] Défaillance totale des moteurs IA ({e})")
            return {"intent": "UNKNOWN", "target": None, "message": "Désolé, service temporairement indisponible."}
```
